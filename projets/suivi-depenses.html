01 — Contexte

Apprendre Kotlin sur un vrai besoin.

C'est mon tout premier vrai projet, un projet d'entraînement. Pour apprendre un langage, je préfère un petit outil concret plutôt qu'une suite d'exercices. Suivre ses dépenses s'y prête bien : un modèle simple (montant, catégorie, date), de la validation de saisie, des calculs et de la persistance.

J'ai d'abord écrit toute la logique en ligne de commande, puis ajouté une interface graphique JavaFX qui réutilise le même gestionnaire. C'est ce projet que je reprends aujourd'hui, en plus ambitieux, avec My Money en Symfony.

02 — Le produit

Deux interfaces, une logique.

// terminal

Version CLI

  • Menu numéroté : ajouter, afficher, totaux, supprimer, sauvegarder
  • Choix parmi 13 catégories (logement, alimentation, transport…)
  • Saisie redemandée tant que le montant ou la date est invalide
  • Import d'un CSV au démarrage, export daté

// javafx

Version graphique

  • Tableau des dépenses avec montants formatés en euros
  • Dialogue d'ajout avec liste de catégories et sélecteur de date
  • Suppression de la ligne sélectionnée, total global et par catégorie
  • Ouverture et enregistrement de fichiers via l'explorateur
03 — Zoom technique

Dans le code.

Refuser le 31 février

Une date au bon format n'est pas forcément une date qui existe. Avec le mode ResolverStyle.STRICT, le parseur de java.time rejette 31/02/2025 au lieu de le corriger silencieusement en 28 février.

Tant que la saisie est invalide, on la redemande : l'utilisateur ne peut pas enregistrer une dépense datée d'un jour impossible.

GestionnaireDepenses.kt kotlin
fun choixDate() : String{
    val formatter = DateTimeFormatter.ofPattern("dd/MM/uuuu").withResolverStyle(ResolverStyle.STRICT)

    while (true) {
        println("\nEntrez la date en format jj/mm/aaaa")
        val date = readln()

        try {
            LocalDate.parse(date, formatter)
            return date
        } catch (_ : DateTimeParseException) {
            println("La date saisie n'est pas valide veuillez recommencer")
        }
    }
}

Un import qui ne plante pas

Les dépenses sont sauvegardées en CSV (montant, catégorie, date) pour pouvoir être rouvertes dans un tableur. À l'import, chaque ligne est vérifiée : une catégorie inconnue est ignorée, et un montant illisible est signalé sans interrompre le chargement des autres lignes.

GestionnaireDepenses.kt kotlin
fun importerCSV(fichier : String) {
    File(fichier).useLines { lines ->
        lines.drop(1).forEach { line ->
            val elements = line.split(";")
            if (elements.size >= 3) {
                try {
                    val montant = elements[0].toDouble()
                    val categorie = elements[1]
                    val date = elements[2]

                    if (categories.contains(categorie)) {
                        ajouterDepense(Depense(montant, categorie, date))
                    }
                } catch (e: NumberFormatException) {
                    println("Erreur dans le fichier CSV : le montant ${elements[0]} n'est pas un nombre valide")
                }
            }
        }
    }
}
04 — Architecture

Comment c'est construit.

Quatre fichiers, et une idée : le gestionnaire porte les données et les calculs, et les deux interfaces ne font que l'appeler. Ajouter JavaFX n'a pas demandé de réécrire la logique, seulement une nouvelle façon de l'afficher.

Application Kotlin · JVM 23 · Gradle
Interfaces Main.kt (menu terminal) · GestionnaireDepensesGUI.kt (JavaFX : tableau, dialogues, sélecteurs de fichiers)
Logique GestionnaireDepenses : liste des dépenses, catégories, totaux, validation, import et export CSV
Modèle Depense : montant, catégorie, date
Persistance Fichier CSV séparé par des points-virgules, nommé à la date du jour
05 — Bilan

Avec le recul.

C'est mon premier projet, et je le relis aujourd'hui avec un œil plus exigeant. Ce qu'il m'a appris, et ce que je ferais autrement :

01

Séparer logique et affichage

Brancher une deuxième interface m'a montré l'intérêt de séparer les couches. Mais certaines fonctions du gestionnaire lisent encore le clavier : elles devraient recevoir des valeurs, pas les demander.

02

Typer les données

Les dates sont stockées en texte et les montants en Double. Aujourd'hui, j'utiliserais LocalDate pour pouvoir trier et filtrer, et des centimes entiers pour éviter les erreurs d'arrondi.

03

Tester

Il n'y a aucun test. Les totaux et l'import CSV sont exactement le genre de code qui se teste facilement : c'est ce que j'ai mis en place ensuite sur Pokémon CLI, avec JUnit 5 et une intégration continue.
